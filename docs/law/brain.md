# LAW — THE BRAIN (five layers, forever recalibrating)

Status: LOCKED v1 (Barticus 2026-09-21). This is the knowledge architecture —
the shape every file and skill is placed into. It is a DYNAMIC OBJECT, not a
frozen spec: layers recalibrate as the system grows. The motto that governs
every change under it: "keep everything, place it better" — never delete lived
knowledge, move it to its correct layer.

## The five layers (load order = the order a working brain touches them)

  LAYER 1 — INDEX          (fast memory, ALWAYS ON)
    Memory + the list of every doc and skill NAME. Pointers only, never bulk.
    Deliberately small: the index routes the brain; it does not hold the work.
    (Hermes: MEMORY.md + USER.md + skill names injected every turn.)

  LAYER 2 — ORCHESTRATOR   (the router = Bob)
    Reads the index, names the tentacle, decides what 3-5 to load. The reason
    the index must be CLEAN — a cluttered index makes the oracle scan instead
    of route. (Hermes: skill routing + KSD-INDEX + the SKILL-INDEX.)

  LAYER 3 — SENSE          (why & what — decode the word)
    Turns a name into its meaning and purpose so nothing is built against the
    wrong shape. vocabulary-law, design-language, and the "why" at the top of
    every law. Answers "WTF is Bart talking about" before work starts.

  LAYER 4 — LANDSCAPE      (big picture + tentacle micro)
    SYSTEM.md = the whole system. The tentacle's HANDOFF/CENSUS/references =
    the zoom. Loaded together on entry to a tentacle: the map of everything,
    then the map of this one thing.

  LAYER 5 — RESOURCE       (known-best-way + truth-of-the-time)
    Skills' bodies + references = "we already know the best way." web search =
    the live truth that changes. Docs retire by role (lifecycle); FACTS refresh
    by lookup — the internet is the clock that keeps the brain from fossilizing.

## The rule that keeps it fast

The whole art is pushing content DOWN the stack: fast memory stays a clean
index; knowledge lives in 3-5 and is pulled only when its tentacle is active.
Do NOT grow Layer 1. A full index is a slow brain.

## The skill shape (one worker per job — locked 2026-09-30)

A skill is a fully-qualified worker for a JOB, named by the job — not a filing
cabinet topic. The crew-roster rule: one worker per part of the stack, owning
its job end to end.

Three layers, mirroring this law's own load order:

  SKILL.md      = the worker's routing table — its sub-jobs and where each
                  reference lives. Loaded on summon; routes, never bulks.
  references/   = the depth. Each sub-job is a reference, lazy-loaded only
                  when that sub-task is reached. Jobs-within-jobs live HERE,
                  not as sibling skills — that is what kills the 1-job-into-4
                  split.
  priority/docket = the OUTER sequence across workers (Layer 2 routing), never
                  encoded inside a single skill.

The graduation rule — the single guard against both failure modes at once: a
sub-job becomes its own skill only when it has its own independent caller (you
summon it directly, not reach it through the parent). "Balance a tyre" stays a
reference inside the tyre fitter; "weld the chassis" is another crew member.
Cut too fine and one job fragments into many; cut too coarse and a god-skill
swallows everything and never loads clean.

## The north star (why — kmedia/docs/law/local-brain.md)

This law is the STRUCTURE of the brain. Its WHY lives in local-brain.md
(locked 2026-08-29): the cloud LLM is the last hole in full-stack ownership;
the end state is a purpose-built, as-small-as-feasible LOCAL model trained
ONLY on the KSD corpus — "no Pokémon stats, no Kardashian birthdays," the
groomed weight cut. That is "the LLM without the pikachu."

THE CORPUS LAW: docs-first is not hygiene, it is corpus curation. Every law,
HANDOFF, and decision log is a training example of how decisions get made
here. The whole spring clean — keep everything, place it better — is building
the training set for the brain that eventually comes home.

## The future (LATER EDITION, not now)

Barticus's read: we can eventually do BETTER than an LLM at Layers 2 and 5.
Deterministic scripts — tentacle-like, flying over FPGAs — land a more accurate
result every time than a probabilistic model can. That is a second/third-edition
product; local-brain.md holds the full north star, this law holds the loading
shape. Today the LLM is the prototyping BOB; the FPGA is the eventual home; the
five-layer Brain is the cortex built now in software, to be the same shape on
the appliance later. godCodemode (present-path) is the body's reflex; this
Brain is what sits above it.

## Parenting

This law is the spine. documentation.md (file ROLES + lifecycle) is its
mechanics — a doc's role says WHEN it retires; this law says WHERE it lives
and in what order it loads. KSD-INDEX.md is Layer 2's surface; the SKILL-INDEX
is the same surface for the skills side. local-brain.md (kmedia) is the north
star this law serves — structure here, destination there.
